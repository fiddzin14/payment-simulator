01 / Mulai dari kredensial.

Buat merchant workspace. Registrasi mengeluarkan secret API key dan webhook signing secret langsung, tanpa email verification atau approval. Simpan keduanya di environment backend. Browser memakai sesi HttpOnly; key API tidak perlu disimpan di frontend. 


            

              Gunakan checkout_url yang dikembalikan untuk membuka instruksi pembayaran. Simpan
              payment ID, external ID, dan idempotency key pada aplikasi. Referensi harus unik per
              pembayaran, termasuk percobaan DP/pelunasan baru.
            

            

              Secret API key ditampilkan sekali. Jika hilang, terbitkan key baru. Jika key dicabut,
              request berikutnya ditolak; transaksi lama tetap ada.

03 / Verifikasi sebelum membuka pesanan.

            

              Atur receiver di Webhook & event. Signature dibuat atas timestamp, satu titik, dan raw
              body JSON yang persis diterima. Periksa toleransi waktu 300 detik dan cocokkan
              payload.id dengan X-Simulator-Event-Id.
            

            

            

              Setelah signature valid, cocokkan merchant, payment ID, external ID, amount, dan IDR
              dengan invoice. GET status dari backend untuk konfirmasi. Simpan event ID unik dan
              perubahan invoice secara atomik; duplikat harus dibalas 2xx tanpa receipt kedua.
            

            

              Initial delivery + 6 retries: 5s, 30s, 2m, 10m, 30m, 2h. Timeout 4 detik/non-2xx
              memicu retry. ID dan payload event tetap, timestamp/signature diperbarui. Manual
              replay tersedia; proses bisnis yang lama sebaiknya diantrekan secara durable.
            

            

              Runnable receiver: examples/merchant-app.mjs. Laravel connection points:
              examples/laravel-integration.md. Panduan PDF mencakup langkah
              menjalankannya.
            

          

          

            
04 / Lifecycle yang konsisten.

            
pending → paid / failed / expired / cancelled
paid → refund.pending → refund.succeeded / refund.failed
expired + late bank receipt → payment.late_received (review)

            

              Status terminal tidak bisa diturunkan. Paid tidak menunggu webhook menjadi delivered.
              Return URL hanya navigasi customer; aplikasi menunggu konfirmasi backend. Dana
              terlambat tidak mengaktifkan ulang pembayaran.
            

            

              POST payment/refund memerlukan Idempotency-Key (8-100 karakter). Reuse dengan body
              yang sama mengembalikan resource yang sama; body berbeda mengembalikan 409. Retain key
              setelah timeout. external_id juga unik per merchant. Refund pending/succeeded
              mereservasi saldo yang dapat dikembalikan.
            

          

          

            
05 / Endpoint reference.

            

              Download OpenAPI 3.1 JSON ↗. Endpoint /v1
              menggunakan secret API key. Endpoint /portal menggunakan sesi workspace. Checkout
              token adalah kapabilitas bearer untuk menjalankan skenario payer sandbox.
            

            

            
HTTP errors

            

              400 invalid JSON; 401 key/login; 403 origin/action; 404 missing/other merchant; 409
              conflict/closed; 413 body limit; 422 validation; 429 rate limit. Semua JSON error
              berisi code, message, dan request_id.
            

          

          

            
06 / Dipakai bersama oleh banyak merchant.

            

              Gunakan satu proses Node.js dengan persistent disk, HTTPS reverse proxy, serta backup
              private data file. Akun/transaksi/key/retry queue disimpan secara atomik di
              .data/gateway.json. Jangan menjalankan cluster atau replika dengan file yang sama.
              Untuk skala lebih besar, gunakan transactional store dan queue terpisah.
            

            
HOST=0.0.0.0
PORT=4179
PUBLIC_BASE_URL=https://sandbox.your-domain.example
ALLOW_LOCAL_WEBHOOKS=false
DATA_FILE=/persistent/lumen/gateway.json

            

              Public webhook harus HTTPS/443. Private/reserved IP, DNS rebinding ke jaringan privat,
              URL credentials, dan redirects diblokir. Local HTTP callback hanya tersedia pada mode
              development. Browser CORS lintas origin tidak diaktifkan; panggil API dari backend.
            

            

              Default controls: 5 signup/jam/IP, 10 login/menit/IP, 120 request/menit per
              merchant/API bucket, 300 request/menit/IP, body JSON 64 KB. Reverse proxy perlu per-IP
              edge limits; server tidak mempercayai forwarded IP headers. Credential request tetap
              otomatis tanpa approval.
            

            

              Nomor/QR/pembayaran hanya uji. Email belum diverifikasi; pemulihan password/email
              belum tersedia. Foto dan database booking tidak diubah. Repository ini belum
              dipublikasikan ke host publik.

Scan QR dari ponsel

        

          QR mengarah ke GET /qris/{token}. Membuka URL langsung mencatat pembayaran simulasi dan
          menampilkan konfirmasi; scan ulang tidak menambah receipt. Nominal selalu mengikuti data
          server. Untuk Wi-Fi lokal, gunakan SCAN_HOST dan SCAN_BASE_URL=http://IP-KOMPUTER:4181.
          Listener ini hanya membuka endpoint QR; portal tetap localhost. Aplikasi tetap
          memverifikasi signed webhook dan status provider.
